# 2 系统关键技术介绍

本章对系统开发所依赖的核心技术进行介绍，主要包括大语言模型、检索增强生成、LangChain 与 LangGraph、FAISS 向量检索、Function Calling 函数调用以及 FastAPI 与 SSE 等技术，为后续系统设计与实现奠定技术基础。

## 2.1 大语言模型与提示工程

大语言模型是一种基于深度神经网络、在超大语料上经过预训练的生成式语言模型。它通过 Transformer 架构中的自注意力机制建模文本序列之间的依赖关系[3]，能够理解自然语言语义并生成连贯、合理的中文或英文文本，同时还具备较强的指令理解、推理与生成能力[4][5]。常见的大语言模型包括 OpenAI GPT 系列、Google Gemini、Anthropic Claude 以及国内的通义千问（Qwen）、文心一言、DeepSeek 等。

在教育场景中，大语言模型可用于回答课程问题、批改主观题、生成练习题、提供学习反馈等[11]。然而，直接使用通用大语言模型存在两点不足：一是模型对特定课程的专业知识掌握有限，面对教材中有明确出处的内容可能给出不准确甚至错误的回答；二是模型生成过程依赖预设的提示（Prompt），回答的风格、结构与约束需要通过提示工程加以引导。

提示工程（Prompt Engineering）是指通过精心设计输入提示，引导大语言模型输出符合预期结果的技术。相关研究表明，通过思维链（Chain-of-Thought）等方式引导模型逐步推理，能够显著提升其在复杂任务上的表现[6][10]。合理设置系统角色、回答要求、输出格式等提示内容，能显著提升生成结果的质量与可靠性。本系统在不同智能体中分别设计了针对性的系统提示（System Prompt），例如要求答疑 Agent 依据参考资料作答并在末尾标注来源，要求批改 Agent 以固定 JSON 结构输出评分与评语，要求出题 Agent 以 JSON 数组输出结构化试题。

## 2.2 检索增强生成（RAG）

检索增强生成（Retrieval-Augmented Generation, RAG）是一种将信息检索与大语言模型生成相结合的范式，最早由 Lewis 等人于 2020 年提出[7]。其基本思路是：针对用户输入的问题，先从外部知识库中检索出相关文本片段，再将检索结果与问题一起拼接进提示，交由大语言模型生成回答。通过引入外部知识，RAG 显著提升了大模型在知识密集型任务上的准确性与可控性，并可在回答中标注知识来源，从而增强结果的可信度[7]。

RAG 的典型流程包括"文档切分—向量化—索引—检索—生成"几个阶段。首先对课程讲义等原始文档进行切分，得到若干文本块；随后利用嵌入模型（Embedding Model）将文本块编码为向量并建立向量索引；在提问时，将问题编码为查询向量，在索引中检索与问题最相似的若干文本块；最后把检索结果作为参考资料交由大语言模型生成回答。

本系统的答疑 Agent 即采用 RAG 技术：教师上传课程知识文档后，系统将其切分并向量化存入 FAISS 向量库；学生提问时，系统从向量库检索相关文本块，与问题一同送入大语言模型，模型据此作答，并在回答末尾输出"参考来源"信息，实现带溯源的智能答疑。

## 2.3 LangChain 与 LangGraph 多智能体框架

LangChain 是一个面向大语言模型应用开发的开源框架，提供了一整套用于构建 LLM 应用的组件与工具，包括模型封装、提示模板、消息处理、工具调用、检索与向量存储抽象、文档加载与切分等[13]。LangChain 通过统一的接口抽象，使开发者能够方便地组合模型、工具与外部数据，快速搭建结构化的 LLM 应用。

LangGraph 是 LangChain 生态中用于构建有状态的多智能体（Multi-Agent）工作流的编排框架[13]。它借鉴图计算的思想，将应用流程建模为一个有向图：图中的节点（Node）对应某一处理步骤（如路由、答疑、批改、出题等），边（Edge）定义了节点间的流转关系，条件边（Conditional Edge）则根据流程中间状态决定下一步走向。LangGraph 通过共享的状态（State）在不同节点间传递数据，使多个智能体能够在同一工作流中协同完成复杂任务，并支持流程的动态路由。

本系统使用 LangGraph 将答疑、批改、出题三个智能体编排到一个工作流中。系统首先通过一个路由节点根据学生提问的关键词判断任务类型，再通过条件边将流程分发到对应的智能体节点执行，实现了多智能体的统一调度与协作。

## 2.4 FAISS 向量检索技术

FAISS（Facebook AI Similarity Search）是 Meta 开源的高性能相似性检索库，专门用于海量向量的最近邻搜索，能够对大规模向量集合进行高效的相似度检索[10][12][15]。FAISS 支持多种索引结构与检索方式，常用于文本向量、图像特征等嵌入向量的检索场景。

在本系统中，FAISS 作为课程知识库的向量索引与检索引擎。系统使用嵌入模型将知识文本块转换为固定维度的向量，并基于 FAISS 构建向量索引；当学生提问时，将问题向量化后在 FAISS 索引中进行相似度检索，返回与问题语义最相近的知识块，作为答疑 Agent 生成的参考资料。FAISS 索引按课程分别保存到本地目录，实现了知识库的持久化与按课程隔离。

## 2.5 Function Calling 函数调用机制

Function Calling（函数调用）是大语言模型的一项能力，指模型在推理过程中根据任务需要，自主决定调用预先定义的外部函数，并返回带有函数名和参数的工具调用（Tool Call）结构化结果，由应用侧执行后把结果回传给模型，从而完成"模型决策—工具执行—结果回填"的闭环。相关研究如 Toolformer 通过让模型自我学习使用工具显著增强了其工具使用能力[9]，而 ReAct 等框架则展示了模型在推理与行动之间交替进行的范式[8]。近年来，以生成式智能体为代表的自主 Agent 研究进一步拓展了模型在模拟任务中自主规划与执行的能力[11]。

Function Calling 机制显著扩展了大语言模型的能力边界，使其能够执行检索数据库、调用计算接口、操作外部系统等原本无法通过文本生成完成的操作，也是构建通用 Agent 的关键技术之一。LangChain 通过 `bind_tools` 绑定工具，将工具描述以结构化形式提供给大语言模型，模型可返回工具调用请求，应用侧执行后再以 Tool 消息回填。

本系统基于 Function Calling 演示了工具的自主调用：答疑与出题 Agent 声明了若干可在流程中申请调用的工具，使大语言模型能够根据上下文自主请求调用，实现了"模型驱动"的工具使用闭环，体现了系统的智能体属性。

## 2.6 FastAPI 与 SSE 技术

FastAPI 是一个基于 Python 的现代 Web 框架，依赖 Pydantic 与 ASGI 实现类型安全的接口开发，支持自动生成交互式 API 文档、请求参数校验与异步处理，具有开发简洁、性能优良、生态成熟等特点[14]。本系统后端采用 FastAPI 构建 RESTful API，并使用 Jinja2 模板实现服务端页面渲染[14]。

服务器推送事件（Server-Sent Events, SSE）是一种基于 HTTP 的服务端单向推送技术。它通过长连接由服务端持续向客户端推送文本数据，客户端使用 `EventSource` 接口即可接收，无需客户端反复请求。由于大语言模型生成回答是逐步产生的，为了提升学生端的交互体验，本系统利用 SSE 实现对话内容的流式输出，配合浏览器端 JavaScript 实时渲染，使回答能够逐段展示，显著改善等待体验。

## 2.7 本章小结

本章介绍了系统开发所使用的关键技术。大语言模型与提示工程为系统提供了自然语言理解与生成能力；检索增强生成使答疑能够基于课程知识库并实现溯源；LangChain 与 LangGraph 提供了大模型应用组装的框架和多智能体编排机制；FAISS 实现了知识库的高效向量检索；Function Calling 扩展了模型的能力边界；FastAPI 与 SSE 则为系统提供了 Web 服务与流式对话的技术支撑。这些技术共同构成了本系统的实现基础。
