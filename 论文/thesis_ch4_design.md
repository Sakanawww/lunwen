# 4 系统设计

本章对系统的总体设计与详细设计进行说明。首先从设计目标与系统框架介绍系统的总体设计，随后按功能模块对系统详细设计进行说明，最后给出数据库的概念结构与逻辑结构设计。

## 4.1 系统总体设计

### 4.1.1 系统设计目标

本系统设计目标是在固定技术栈下，构建一个基于 Agent 的、稳定可用的课程助教系统，满足学生答疑、教师批改与出题、管理员管理的教学辅助需求。具体目标包括：

（1）多智能体协作。依托 LangGraph 将答疑、批改、出题三个智能体编排到一个工作流中，通过关键词路由实现任务分流与统一调度。

（2）检索增强与溯源。答疑基于课程知识库进行检索增强生成，回答带来源引用，保证答案的准确性与可信度。

（3）流式交互。对话内容采用 SSE 流式输出，实时展示生成过程，改善用户体验。

（4）三端角色隔离。实现学生、教师、管理员三类角色的统一登录与基于角色的权限控制。

（5）可维护可扩展。系统按模块化分层组织，具备良好的可维护性与扩展性，大模型供应商可配置、可切换。

### 4.1.2 系统总体框架

系统采用前后端分离的服务架构。前端负责页面渲染与交互，后端提供业务接口并统一编排智能体，数据层负责数据的持久化与知识库管理。系统总体框架图如图 4.1 所示。

【图4.1 系统总体框架图】

系统的分层结构如下：

（1）展示层（前端）。基于 Jinja2 模板实现学生端、教师端、管理员端的页面，配合少量原生 JavaScript 实现流式对话、表单交互等。

（2）接口层（API）。基于 FastAPI 提供的 RESTful 接口，包括认证、答疑、知识库、作业批改、智能出题、学情看板等接口，负责参数校验、会话管理与权限控制。

（3）智能体层（Agent）。包含答疑、批改、出题三个智能体，以及基于 LangGraph 的编排图，实现多智能体的路由、执行与协作。

（4）检索与知识层。实现课程知识文档的解析、切分、向量化与 FAISS 索引检索，为答疑 Agent 提供检索上下文。

（5）数据层。基于 MySQL 存储用户、课程、知识库、对话、作业、试题等业务数据；FAISS 向量索引按课程持久化到本地。

## 4.2 系统详细设计

系统按功能划分为认证管理、智能答疑、知识库管理、作业批改、智能出题、学情看板等模块。下面按模块对核心功能的设计进行说明。

### 4.2.1 认证管理模块设计

认证管理模块负责用户的注册、登录与登出，并实现基于角色的访问控制。用户在登录页面输入用户名与密码，系统校验通过后建立本地会话，将会话令牌写入浏览器 Cookie；后续请求通过依赖注入验证会话令牌，还原当前用户。系统根据用户角色（学生、教师、管理员）跳转到对应的功能界面。用户登录流程如图 4.4 所示。

【图4.4 用户登录流程图】

权限控制方面，答疑与学情相关接口要求登录用户，知识库上传、作业批改、出题接口要求教师或管理员角色，未登录或越权请求将分别返回 401 与 403 状态码。

### 4.2.2 智能答疑模块设计

智能答疑模块是本系统的核心功能，面向学生用户，基于 RAG 技术实现带溯源的流式多轮答疑。其核心流程为：学生提交问题后，系统基于会话关联的课程构建知识库对象，从 FAISS 索引中检索与问题相似度最高的若干知识块，将检索上下文与学生问题、系统提示一起组装为消息序列，调用云端大语言模型进行生成；模型输出通过 SSE 以流式方式逐步推送到前端，并在回答末尾携带最终正文与来源引用信息。答疑模块工作流程如图 4.5 所示。

【图4.5 智能答疑模块流程图】

在溯源方面，系统要求大语言模型在回答末尾输出"参考来源：文档名·片段序号"格式的来源行，答疑 Agent 在流式输出结束后调用来源解析逻辑，将来源行从正文中剥离，得到最终的清洁正文与来源列表；该来源列表随 SSE 末尾数据帧发送给前端展示，并随回答一同写入数据库。智能答疑模块时序图如图 4.6 所示。

【图4.6 智能答疑模块时序图】

### 4.2.3 知识库管理模块设计

知识库管理模块面向教师与管理用户，负责课程知识文档的入库与管理。支持 .txt、.md、.pdf 格式文档的上传。上传后系统读取文档内容，按照 500 字符的块大小与 50 字符的重叠区间对文本进行切分，得到若干知识块；随后利用嵌入模型将每个知识块编码为向量，构建并保存 FAISS 向量索引；同时将文档元数据与知识块内容写入数据库。各课程的知识索引按课程 ID 分别保存，实现知识库的按课程隔离。知识库文档入库流程如图 4.7 所示。

【图4.7 知识库文档入库流程图】

### 4.2.4 作业批改模块设计

作业批改模块面向教师与管理员，实现对学生作业的 AI 辅助批改。系统以统一评分提示词引导批改 Agent 对作业作答进行评分，并以固定 JSON 结构输出百分制得分与针对知识点的评语、错误指出与改进建议。批改完成后，系统创建批改记录并写入数据库，同时将作业提交状态置为"已批改"。作业批改流程如图 4.8 所示。

### 4.2.5 智能出题模块设计

智能出题模块面向教师与管理员，依据课程、知识点、题目数量与难度批量生成试题。教师设置知识点、数量与难度后，系统调用出题 Agent，以结构化 JSON 形式生成覆盖选择、填空、简答等多种题型的试题（包含题干、选项、参考答案与难度等级），并将生成的试题逐条写入试题库，供页面展示。智能出题流程如图 4.9 所示。

学情看板模块面向教师与管理员，对某课程的整体学情进行统计展示。系统通过数据库聚合查询，统计选课人数、作业提交数量、已批改数量、平均得分、知识文档数量、试题数量与答疑消息数量等指标，并以数据看板形式呈现，帮助教师了解课程整体教学与学习情况。学情看板数据统计流程如图 4.10 所示。

## 4.3 数据库设计

### 4.3.1 数据库概念设计

在数据库概念设计阶段，通过绘制 E-R 图（实体-联系图）建立系统的概念模型。系统涉及的主要实体包括用户、学生、教师、课程、知识文档、知识块、会话、消息、作业、作业提交、批改记录、试题、学情记录、Agent 配置与系统日志等。

各实体间的联系如下：用户与课程之间存在授课联系（教师授课）与选课联系（学生选课）；课程与知识文档之间、知识文档与知识块之间存在包含联系；课程与作业之间、作业与作业提交之间存在包含联系；作业提交与批改记录之间存在对应联系；课程与试题之间、课程与学情记录之间存在包含联系。系统核心数据 E-R 图如图 4.11 所示。

【图4.11 系统核心数据 E-R 图】

### 4.3.2 数据库逻辑结构设计

## 4.4 本章小结

本章对系统进行了设计。总体设计明确了系统分层架构、设计目标与整体工作流程，并给出了多智能体编排流程；详细设计按认证管理、智能答疑、知识库管理、作业批改、智能出题、学情看板等模块说明了核心流程与时序关系；数据库设计给出了概念结构的 E-R 图与逻辑结构的数据表设计，为系统实现奠定了基础。
