# ADR-002: 使用 FAISS 而非 Chroma

## 状态

已采纳

## 上下文

在实现 RAG（检索增强生成）功能时，需要选择一个向量数据库来存储和检索课程知识库的嵌入向量。系统需要将课程文档切分、向量化，并支持相似度检索。

## 决策

选择使用 **FAISS** 作为向量数据库，而非 Chroma 等其他向量数据库。

## 理由

1. **轻量级**：FAISS 是一个纯内存/文件级的向量索引库，无需额外的服务进程，简化了部署。

2. **高性能**：Facebook AI Research 开发，针对相似度检索进行了高度优化，支持 GPU 加速。

3. **无需额外服务**：与 Chroma 等需要独立服务进程的向量数据库相比，FAISS 可以直接嵌入到应用中，降低了系统复杂度。

4. **适合演示系统**：作为毕业设计演示系统，FAISS 的轻量级特性符合简化部署的目标。

## 后果

### 正面影响

- 部署简单，无需额外服务
- 检索速度快
- 索引可持久化到文件系统 (`data/faiss_index/`)

### 负面影响

- 不支持分布式扩展
- 不支持实时更新（需要重建索引）
- 功能相对单一（仅支持相似度检索）

## 使用方式

```python
# 向量索引路径
index_path = f"data/faiss_index/course_{course_id}/"

# 检索流程
上传文件 → 解析文本 → 切分 (500 字/块，50 字重叠) → 向量化 → FAISS 索引 → MySQL 元数据
```
