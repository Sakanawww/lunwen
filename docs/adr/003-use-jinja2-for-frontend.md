# ADR-003: 使用 Jinja2 而非 Vue/React

## 状态

**已废弃** — 已被 [ADR-007](007-use-vue3-spa-for-frontend.md) 替代。

本决策曾作为项目初期的前端选型，后因系统功能演进（多角色路由、复杂状态管理、流式 SSE 答疑、ECharts 数据看板等）在 SSR 模板下维护成本过高，已于后续迁移至 Vue 3 SPA。详见 ADR-007。以下内容保留以记录决策历史。

---

## 上下文

在构建课程助教系统的前端时，需要选择一个合适的前端技术栈。系统需要支持多个角色（学生/教师/管理员）的不同页面，包括聊天、知识库管理、作业批改、试题管理等功能。

## 决策

选择使用 **Jinja2 模板 + 原生 JavaScript** 作为前端技术栈，而非 Vue/React 等现代前端框架。

## 理由

1. **毕业设计要求**：本项目是毕业设计演示系统，采用传统的服务端渲染架构符合项目定位。

2. **简化部署**：Jinja2 是 FastAPI 内置支持的模板引擎，无需额外的构建流程和前端打包工具。

3. **技术栈统一**：后端使用 Python，前端模板也使用 Python 生态的 Jinja2，降低了技术栈复杂度。

4. **开发效率**：对于演示系统，Jinja2 模板可以直接在服务端渲染，避免了前后端分离带来的 CORS、认证等额外复杂度。

## 后果

### 正面影响

- 部署简单，无需前端构建流程
- 前后端代码在同一项目中，便于维护
- 页面加载速度快（服务端渲染）

### 负面影响

- 不支持组件化开发
- 前端状态管理需要手动实现
- 不适合构建复杂的单页应用（SPA）

## 前端架构

```
┌─────────────────────────────────────────────────────────┐
│                     前端层 (Jinja2)                      │
│  login.html | chat.html | dashboard.html | kb.html ...  │
├─────────────────────────────────────────────────────────┤
│                     API 路由层 (FastAPI)                  │
└─────────────────────────────────────────────────────────┘
```
